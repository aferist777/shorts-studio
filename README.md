# Shorts Studio

Десктопное приложение (PySide6): тема → готовый вертикальный ролик. Сценарий,
озвучка, картинка, субтитры и сборка — свой ffmpeg-конвейер внутри одного окна,
без облачных редакторов и таймлайна.

## Запуск

```
pip install -r requirements.txt
```

Дальше `run.bat` (или `python app/main.py`).

Ключи вводятся в настройках приложения и ложатся в системное хранилище учётных
данных (`keyring`), а не в файлы репозитория. Для рендера нужен `ffmpeg`.

Минимум для первого ролика — ключ LLM. Озвучка по умолчанию Edge TTS:
бесплатно, без ключа и сразу с потайминговкой по словам, из которой растут
субтитры.

## Шаги

Воркспейс — это шаги слева направо, у каждого своё превью:

1. **Сценарий** — из темы или из идеи, взятой из базы (см. ниже).
2. **Голос** — Edge TTS даром или ElevenLabs, если нужен голос получше.
   Тайминги по словам приезжают вместе с аудио.
3. **Медиа** — пул футажа и кадров под куски сценария.
4. **Рендер** — субтитры, движение, склейка, вертикальный кадр, вывод.

Долгие операции уходят в воркер (`app/services/worker.py`), окно не морозится,
прогресс виден на месте. Медиа показывается превьюшками; полный размер —
только в режиме просмотра.

## База идей

Ролик не обязан начинаться с темы в пустом поле. Можно скормить ссылку на
YouTube: `yt-dlp` вытаскивает аудио и субтитры, STT расшифровывает (Grok, а не
автосубтитры YouTube — они слишком грязные), и из транскрипта рождается база
идей, из которой отпочковываются отдельные проекты. Длинное аудио режется так,
чтобы куски пролезали под лимит загрузки в 25 МБ, а разобранные видео
переиспользуются, а не качаются заново.

Сценарий пишется хук-вперёд: сначала цепляющее начало, потом уже текст по
транскрипту.

## Фрагменты и пул

Исходное видео скачивается один раз, режется на фрагмент под каждый проект и
выбрасывается. Полная загрузка — рабочий файл; выживает один слайс, лежащий в
папке своего проекта, поэтому удаление проекта уносит его футаж с собой и
ничего не остаётся осиротевшим или общим. Резка копирует потоки, а не
перекодирует: на 1080p с ключевыми кадрами раз в четыре секунды это 0.3 с
против 28.7 с.

Фрагмент — непрерывный кусок чужого монтажа, а значит, склейки в нём уже есть:
между картиной и картой, между архивом и ведущим. `app/services/cutter.py`
находит эти швы ffmpeg'ом, без того чтобы кто-то отсматривал всё целиком, и
разбирает фрагмент на b-roll.

Всё нарезанное и все сохранённые кадры складываются в **пул** проекта. Сцена
берёт из пула, а не идёт искать сама: сначала собрать, потом раздать.

## Рассказчики и стиль

`data/narrators.json` — набор голосов-стилей. Рассказчик строится из
собственных текстов автора: скармливаешь свои тексты, из них извлекается манера
речи, и дальше сценарии пишутся ею, а не усреднённым машинным тоном.

`data/styles/` — промпты визуального стиля для генерируемых кадров
(`app/services/kie_images.py`, nano-banana через kie.ai). Из граблей, стоивших
времени: референсы принимаются только публичными URL, поэтому локальный файл
сначала надо где-то захостить, а CDN с результатом отвечает 403 на дефолтный
user-agent.

```
shorts-studio/
├── app/
│   ├── services/
│   │   ├── llm/        Anthropic SDK + OpenAI-совместимые провайдеры
│   │   ├── tts/        Edge и ElevenLabs
│   │   ├── ideas/      YouTube, STT, фрагменты, темы
│   │   ├── cutter.py   поиск склеек и нарезка b-roll
│   │   ├── pool.py     собранный футаж проекта
│   │   ├── frames.py   кадры и движение
│   │   ├── kie_images  генерация картинок
│   │   ├── thumbs.py   превьюшки
│   │   ├── render.py   сборка через ffmpeg
│   │   └── subtitles.py
│   ├── widgets/        шаги воркспейса и диалоги
│   └── store.py        проекты и настройки на диске
├── data/               narrators.json и styles/ — остальное рантайм
├── tools/snapshot.py   скриншот окна
└── run.bat
```
